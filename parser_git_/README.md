## Запуск

Источник может быть локальным файлом или ссылкой на Google Таблицу
(доступную "по ссылке") — тип определяется автоматически. Для ссылок
на Google Таблицы есть два способа получения данных:

**Приоритетный способ — Google Sheets API** (быстрее, не скачивает файл
целиком, устойчив к таймаутам, которые бывают у xlsx-экспорта Google).

# ключ можно передать флагом...
python main.py "https://docs.google.com/spreadsheets/d/ID/edit?usp=drive_link" \
    --api-key ВАШ_КЛЮЧ --out schedule.json

# ...или один раз положить в переменную окружения
export GOOGLE_SHEETS_API_KEY=ВАШ_КЛЮЧ      # Windows (PowerShell): $env:GOOGLE_SHEETS_API_KEY="ВАШ_КЛЮЧ"
python main.py "https://docs.google.com/spreadsheets/d/ID/edit?usp=drive_link" --out schedule.json

**Без ключа** — автоматически используется резервный способ (полная
выгрузка xlsx через `.../export?format=xlsx`, как было раньше). Это
работает, но медленнее и иногда упирается в таймаут на скачивании
сгенерированного Google файла — программа выведет предупреждение об
этом в stderr.

**Локальный файл** и **публичная ссылка на Яндекс.Диск** — как раньше,
без API-ключа (Sheets API к ним неприменим, это специфика Google):

```bash
python main.py "1 модуль - Ф-т ИМиКН - БАК Компьютерные науки и технологии.xlsx" --out schedule.json
python main.py "https://disk.360.yandex.ru/i/XXXXXXXXXXXXXX" --out schedule.json
```

`--force-xlsx` заставляет использовать xlsx-экспорт даже для Google-ссылки,
даже если ключ передан (пригодится для сверки/отладки двух путей).

По умолчанию обрабатываются все листы, название которых содержит "курс"
(1/2/3/4 курс). Можно указать конкретные листы:

```bash
python main.py файл.xlsx --sheets "1 курс,2 курс"
```

В stdout выводится сводка по каждому листу (число групп/занятий/заметок и
предупреждений по уровням критичности). Если хотя бы одно предупреждение
уровня `critical` — процесс завершается кодом 1: **такое расписание
нельзя публиковать как рабочее** (ТЗ, раздел 4, 20).

## Тесты

```bash
pytest tests/ -v
```

Покрывают все 15 сценариев из ТЗ (раздел 32) плюс edge-cases, реально
найденные в файле (опечатки в датах, отмена занятия, точечное
исключение по времени, разделитель-дефисы, "Вакансия" вместо ФИО,
несколько преподавателей через запятую и т. д. — см. `ANALYSIS.md`).

## Структура

```
schedule_parser/
├── main.py              # оркестрация: source -> parser -> normalizer -> validators -> JSON
├── core/
│   ├── source.py        # локальный файл / Google Sheets (xlsx-резерв) / Яндекс.Диск / прямая ссылка
│   ├── gsheets_api.py   # ПРИОРИТЕТНЫЙ путь для Google-ссылок: Google Sheets API v4, без скачивания файла
│   ├── parser.py        # извлечение сырой структуры листа из openpyxl.Worksheet (локальные файлы)
│   ├── normalizer.py    # разбор текста ячейки в Lesson/ScheduleNote — общий для обоих путей
│   ├── models.py        # dataclass-модели предметной области
│   └── validators.py    # sanity-проверки перед публикацией
├── tests/
│   ├── test_parser.py
│   ├── test_normalizer.py
│   ├── test_source.py       # моки HTTP — без реальной сети
│   └── test_gsheets_api.py  # моки Sheets API — без реальной сети
├── ANALYSIS.md           # разбор реального файла (обязателен по ТЗ)
└── requirements.txt
```
